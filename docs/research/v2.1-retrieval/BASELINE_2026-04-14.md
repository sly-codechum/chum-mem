## Quality Baseline

### 1. Memory noise

Broad continuation/retrieval queries still surface unrelated artifacts.

Observed:
- `retrieval_noise`: `relevantTop5 = 2`, `irrelevantTop5 = 3`
- `continuation_noise`: `relevantTop5 = 0`, `irrelevantTop5 = 4`

Interpretation:
- broad `mem_search` still retrieves noisy summaries/bugs from unrelated session history
- continuation-style queries are especially vulnerable to irrelevant top hits

### 2. `context_build` quality

The endpoint is fast but not useful enough.

Observed:
- repository-only objective: `typedSectionFillRate = 0.25`, `sourceOnlyBudgetShare = 1.00`
- memory-only objective: `typedSectionFillRate = 0.125`, `sourceOnlyBudgetShare = 0.916`
- hybrid objective: `typedSectionFillRate = 0.00`, `sourceOnlyBudgetShare = 0.971`

Interpretation:
- most of the token budget is effectively spent on provenance-heavy output
- repository-only and hybrid objectives are not producing authority-aware typed evidence packs
- this validates the earlier claim that `context_build` is fast but too weak as an evidence assembler

### 3. Repository search accuracy

Repository search is partly good, but not yet strong enough to replace grep reliably.

Observed:
- exact file path: top-1 exact hit
- exact symbol: top-1 exact hit
- doc heading: top-3 hit only, top-1 is the wrong symbol (`CONTEXT_BUILD_SEARCH_LIMIT`)
- rationale lookup: top-1 exact hit, but on an irrelevant vendored/pdf-lib rationale node rather than repo-local intent

Interpretation:
- exact path and exact symbol search are already solid
- section/document search still loses to nearby symbol noise
- rationale search needs stronger locality and file relevance bias

### 4. Cross-layer separation

Observed:
- repository search produced `repositorySessionLeakCount = 0`
- session hub nodes were all `session` nodes

Interpretation:
- layer separation is working
- the remaining problem is not layer mixing but poor retrieval/packing quality within the available layers

## Baseline Conclusions

The pre-change `v2.1` runtime confirms:
- graph/report/export read paths are the main latency bottleneck
- `context_build` quality is the main context-engineering bottleneck
- memory retrieval remains noisy on broad continuation-oriented prompts
- repository search needs better ranking for document/rationale lookups before it can replace grep confidently

These numbers and examples are the benchmark reference for the post-change comparison.
